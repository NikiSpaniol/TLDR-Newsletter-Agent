LLMS COULD CONTROL THEIR HOST MACHINES BY EXPLOITING INFERENCE ENGINES (6 MINUTE READ)

A researcher explores how malicious large language models could gain control of their host machines by exploiting vulnerabilities in inference engines like vLLM and SGLang.

A researcher explores how malicious large language models could gain control of their host machines by exploiting vulnerabilities in inference engines like vLLM and SGLang. The attack works by having an LLM emit token sequences that exploit bugs in the software parsing those tokens into readable outputs, potentially executing arbitrary code on the high-value GPU host. A real vulnerability (CVE-2025-9141) in vLLM's XML tool parser previously used `eval()` on tool-call arguments, allowing code execution, though a maintainer force-merged the vulnerable code despite automated warnings. Modern inference engines are complex systems supporting hundreds of model architectures and dozens of chat templates, creating numerous opportunities for parser bugs that could allow token sequences to be misinterpreted as executable code. The article argues that as open-weight LLMs become more powerful and run on less-scrutinized inference engines, the risk increases, and defenses like separating GPU and parsing hosts and treating all emissions as untrusted data are recommended.

SPECULATIVE PROGRAMMATIC TOOL CALLING (12 MINUTE READ)

This article introduces Speculative Programmatic Tool Calling (sPTC), a technique that pre-launches tool calls from partially generated code while an LLM is still streaming tokens, rather than waiting for complete generation.

This article introduces Speculative Programmatic Tool Calling (sPTC), a technique that pre-launches tool calls from partially generated code while an LLM is still streaming tokens, rather than waiting for complete generation. Inspired by speculative execution in CPUs and speculative decoding in LLMs, sPTC addresses latency bottlenecks in code-execution-based AI harnesses by overlapping high-latency tool calls (especially sub-LLM or sub-agent calls) with ongoing token generation. The author demonstrates the approach through a "shadow REPL" that safely executes partial code to identify and pre-compute tool call inputs, handling cases from simple string literals to conditional logic and variable dependencies. Testing on the OOLONG dataset with Qwen3-30B showed speedups of 1-1.2x for Recursive Language Models across different load conditions, with overhead kept minimal through careful design choices around what can safely be speculated. The implementation distinguishes between speculatable tool calls based on input purity, blocking unsafe functions like file operations, and tracks unique instances to avoid incorrect output caching.

The article documents a cascading supply-chain crisis across AI infrastructure components, termed the "Bullwhip Effect." Beginning with GPU scarcity in early 2023 when Nvidia H100 rental rates exceeded $9 per hour post-ChatGPT launch, bottlenecks sequentially migrated to memory, CPUs, and storage over subsequent years, each wave amplified by multi-year manufacturing lead times. When manufacturers redirected capacity toward High Bandwidth Memory, enterprise SSD prices surged 80% in a single quarter and DRAM prices climbed in the low-60s percentage range. By late 2025, agentic workflows inverted the CPU-to-GPU ratio from 1:8 to 1:1, driving Intel server CPU prices up 27% year-over-year despite falling unit volumes, while by 2026 cloud architects retreated to slower hard disk drives after flash storage reached $150 per terabyte. The infrastructure crisis now centers on data center construction—facilities now cost $20 billion per gigawatt with electrical systems consuming half the budget, construction costs tripling to $1,033 per square foot, and transformer lead times extending to three years with turbine manufacturers sold out through 2029-2031. The article warns that over $2 billion in capital infrastructure committed for 2027-2028 delivery faces severe overcapacity risk if software revenue growth fails to justify the $20b/GW facility economics.

VOCAB BREAK (4 MINUTE READ)

Claude's tokenizer contains only about 15,000 vocabulary entries, dramatically smaller than competitors like Qwen 3.8's 250,000-token vocabulary, reversing the industry trend of larger vocabularies.

Claude's tokenizer contains only about 15,000 vocabulary entries, dramatically smaller than competitors like Qwen 3.8's 250,000-token vocabulary, reversing the industry trend of larger vocabularies. The likely reason is that Anthropic is avoiding a gradient bottleneck in the softmax layer during training: when backpropagating loss through a large vocabulary space (V=250k) compressed to a smaller hidden dimension (D=8,192), information is lost because the gradient change has rank at most 2D. By shrinking the vocabulary from 50,000 entries in Claude 3 to 16,000 today, Anthropic sidesteps this bottleneck, though it requires handling rare tokens and non-English languages with subword and UTF-8 fallbacks, increasing token-per-text costs by 1.2-2x. The tradeoff appears favorable: eliminating memory-intensive projection layers, avoiding glitch tokens, and ensuring all tokens receive training outweigh the computational overhead of processing more tokens.

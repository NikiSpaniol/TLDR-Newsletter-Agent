CLAUDE-SHAPED SCIENCE (24 MINUTE READ)

Prof.

Prof. Matthew Schwartz describes how he developed BootLoops, an open-source toolkit that lets Claude solve quantitative science problems by focusing on "Claude-shaped" problems—ones where the model's strengths (coding, mathematical breadth, pattern recognition across domains) naturally align with scientific needs rather than fighting its limitations. Rather than using Claude like a human scientist, Schwartz identified that the model excels at computational tasks spanning multiple fields: it computed 15 previously unsolved elliptic Feynman integrals, solved a 30-year-old population genetics equation, discovered gene conversion mechanisms in 5.7 billion genetic pairs, and contributed to advances across ecology, phylogenetics, economics, linguistics, cosmology, and other fields—though Schwartz found that domain experts were needed to refine technically correct but scientifically unremarkable initial results into meaningful contributions. Over three months, Schwartz and Claude produced 36 manuscripts across 18 fields with 19 coauthors, demonstrating how iterative collaboration between AI and human specialists can overcome the "impedance mismatch" between what scientists want and what current LLMs do well. The article emphasizes practical management lessons: Claude lacks time sense, tends to declare premature victory, requires human oversight of all outputs, and needs clear success criteria, but these are training problems the models will outgrow.

AI21 Labs manages a 10,000-GPU fleet across multiple teams using Kueue, an open-source Kubernetes-native job queueing system, moving from manual negotiations in internal messaging channels to fully automated workload scheduling. The company implemented two versions: v0.10 established guaranteed, preemptible, and on-demand capacity pools with three developer-facing labels (spend, preemptibility, priority) for queue routing, but encountered fairness gaps when teams couldn't be balanced fairly on multi-node workloads without preemption. The system now automatically routes all workloads to appropriate queues, manages preemption decisions intelligently, and keeps utilization near 100% while allowing researchers to focus on science rather than resource negotiation.

VX (WEBSITE)

Vx is a systems programming language designed for heterogeneous computing that integrates CPU, GPU, NPU, and accelerator memory into its type system to catch data-locality bugs at compile time rather than runtime.

Vx is a systems programming language designed for heterogeneous computing that integrates CPU, GPU, NPU, and accelerator memory into its type system to catch data-locality bugs at compile time rather than runtime. The language treats memory location as part of a variable's type, requiring explicit `transfer()` calls between memory spaces even when hardware boundaries are transparent, and uses machine files that declare specific hardware capabilities (memory hierarchy, bandwidth, interconnect) to verify that code placements are feasible before compilation. Vx's compiler front-end uses 256-bit identifiers for all symbols and implements parallel compilation that produces byte-identical output regardless of thread count, and it supports multiple backends including x86/ARM via LLVM, NVIDIA GPUs via NVVM/PTX, and Apple accelerators via CoreML. The language catches six classes of bugs: address-space violations, memory capacity overflows, broken asynchronous transfers, use-after-move errors, unreachable topology transfers, and undefined autodiff regions. The project ships verified machine files for processors like H100, H200, M4, and MI300X, and positions itself for computationally correct, performance-sensitive code rather than exploratory machine learning work where architecture changes dynamically.
